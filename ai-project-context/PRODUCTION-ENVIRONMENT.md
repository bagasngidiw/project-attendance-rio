### Platform note for Vercel

Because the frontend hardcodes the relative `/api/v1` base, Vercel must proxy API traffic to Render.
This is a **platform rewrite rule**, not an env var. In `vercel.json` (or the Vercel dashboard Rewrites section), add:

```json
{ "rewrites": [{ "source": "/api/(.*)", "destination": "https://<render-app-url>.onrender.com/api/$1" }] }
```

No environment variables need to be set on Vercel unless you later add `VITE_*` build-time config (not present today).

## Never expose to frontend

The following are **backend-only secrets**. They must never appear in frontend code, `VITE_*` vars,
client bundles, or browser-visible responses:

| Variable | Why it must stay secret |
|---|---|
| `MONGO_URI` | Contains the Atlas database user/password. Exposure = direct database compromise. |
| `JWT_SECRET` | Forging valid tokens becomes trivial. |
| `SEED_SUPER_ADMIN_PASSWORD` | Seeded superadmin bootstrap credential. |
| `AUDIT_CHAIN_SALT` | Predictable/leaked salt weakens the tamper-evident audit chain. |
| `PORT` / all other backend vars | Backend-only configuration; not secrets but never needed client-side. |

The backend already never logs or exposes these values (`config.js` header comment; `AUDIT_CHAIN_SALT`,
`JWT_SECRET` are never returned in API responses).

## Production safety warnings

Development fallbacks that **must be overridden** on Render:

1. **`MONGO_URI`** — fallback is `mongodb://127.0.0.1:27017/attendance_db`. Without it, the server cannot start (it exits with code 1 before `listen`). **Also: the previous Atlas credential was pushed to GitHub history and must be rotated in MongoDB Atlas before it is reused.**
2. **`JWT_SECRET`** — dev fallback `dev-only-insecure-secret-change-me` is **rejected at boot in production** (throws), so this is enforced. Set a long random value.
3. **`SEED_SUPER_ADMIN_PASSWORD`** — dev fallback `SuperAdmin2026!` is a **known public string**. If unset in production, the superadmin is seeded with it. Override and change the seeded password after first login.
4. **`SEED_DEMO_DATA`** — default `"true"` seeds demo employees/roles/requests on every boot. Set `"false"` in production.
5. **`CORS_ORIGINS`** — default `http://localhost:5173`. Browser clients from the real frontend origin will be blocked until set.
6. **`AUDIT_CHAIN_SALT`** — dev fallback is predictable. Set a stable random value **and never change it afterwards**; changing it breaks hash-chain verification of existing audit records.
7. **`NODE_ENV`** — defaults to `development`. Set `production` so JWT-secret enforcement and prod error handling activate.
8. **Local disk storage** — `BRANDING_ASSETS_DIR`, `ATTENDANCE_MEDIA_DIR`, `ATTACHMENT_ASSETS_DIR` default to the app working directory on **ephemeral local disk**. Render restarts/deploys wipe these files (uploaded logos, attendance selfies, attachments are lost). In production, either mount a Render **persistent disk** and point these three variables at it, or accept ephemeral storage.
9. **Rate limiting** — the global rate limiter is **commented out** (`server.js:556`); only password-recovery routes use it. If you want global rate limiting in production, it must be re-enabled in code (out of scope of this document).
10. **`backend/.env`** — the local `.env` file must **never** be deployed to Render. On Render, set all variables in the dashboard/`render.yaml`; do not ship `.env` with the repo (it is now git-ignored and untracked).
